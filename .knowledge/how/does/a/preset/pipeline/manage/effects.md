components/core/kest_pipeline.c owns the ordered linked effect list. Append instantiates a descriptor and assigns an ID; remove disables and marks the matching effect for retirement, then unlinks/frees the list node. Move relinks nodes by position. The pipeline can clone, count, build a transfer batch, rectify IDs, activate/deactivate LFOs and recalculate FPGA positions.

David directs deletion markers inside resource payloads, handled by the existing control loop. MEM, LFO, DELAY and FILTER payloads have atomic delete_requested markers. free_effect atomically marks the owner dead, marks its resources and hands the owner to control through an intrusive atomic list. Duplicate marking does not submit the owner twice. No allocation is needed for this handoff; it includes inactive effects and survives clearing/replacing the active-resource cache.

Each control tick holds the existing recursive UI lock, serializing ordinary UI list edits and final reclamation with its model borrows. Smoothing remains a separate task and is not covered by this control-task lock. The smooth-target owner describes the retained lookup/atomic-write approach and outstanding pointer-lifetime, ID-reuse and persistence concerns. Control collects retired owners before draining notifications. Dead owners and marked resources no longer propagate updates or dispatch reads. At a READY tick's end, after temporary updates/write lists have been consumed, control removes cached resource borrowers and queues one callback on the existing SPI FIFO. That callback marks prior SPI callbacks finished. Queue rejection retains the owner for another tick; REPROGRAM retains it until the borrowed programming work is consumed. After SPI completion, a subsequent control tick schedules final reclamation through kest_ui_async_call. The view remains alive until this UI-task callback; control retains the owner if scheduling fails. Without UI support, control reclaims directly. Control/SPI borrows finish before the retired pool slot is returned; lifetime safety for the independent smoothing task remains unqualified.

On the UI task, final reclamation first cancels queued effect updates, page-entry callbacks, widget refreshes and LFO callbacks/timers, then releases the effect view. Widget destruction cancels its refresh callback/timer and clears its parameter backlink; view destruction releases widget lists, the complete nested settings page, view data and panel. Embedded settings-widget cleanup also deletes containers reparented onto backstage. It then releases parameters/settings through their existing typed allocators, band-mode options, heap-cloned resource wrappers/payloads, filter coefficient containers, block/driver containers and instance scope/dependency containers, then the effect mutex and owner through its allocator. Descriptor names, expression graphs and static LUT resources referenced by blocks remain borrowed. Resource clones currently use the tracked heap, despite the initialized typed resource allocator; live strategy changes still require an agreed allocator lifetime.
