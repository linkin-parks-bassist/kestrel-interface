The firmware UART console is implemented in main/kest_console.[ch] using the pinned IDF console REPL on UART0 at 115200 baud, with prompt kest>. app_main starts it after posting the startup event; startup failure is logged without aborting the existing system.

Commands are help, info (firmware/IDF/tick rate/task count), heap (free/minimum/largest/internal memory), uptime, ui-tree, tap X Y, touch down X Y, touch move X Y, touch up, fpga-read ADDRESS, fpga-read32 ADDRESS, fpga-status, dsp, and eff-file. dsp inspects the active preset under the UI lock, printing effects, block counts and resource handles; memory resources include resolved addresses, cadence and the atomic latest sample. fpga-status asynchronously prints the raw status byte and decoded flags or a SPI driver error. Addresses accept decimal or 0x hex; memory read results arrive asynchronously as raw unsigned payloads or negative transport errors. SPI owns and frees the generic read specification; it does not borrow a console stack object.

fpga-read32 uses a 24-bit word-aligned address and prints the asynchronous four-byte result as eight hex digits. Address 0 is magic and address 4 is build flags under the shared numeric/protocol contract. Invalid alignment or address range is rejected before queueing. It uses the existing generic read callback, and the SPI task owns the allocated request through completion. The command is installed in the current read32 firmware. /tmp/kestrel-timing-read32-hil.log verifies address 0 returning 0x4b455354 and address 4 returning 0x00000006 through the physical SPI link. Automatic startup probing and capability-aware instruction rejection/lowering remain planned.

UI commands create a separate LVGL pointer device and change its state under the existing UI lock. LVGL reads it on the UI task, exercising normal hit-testing, press/release/drag handling and widget callbacks. A tap holds for 80 ms from its first input read; repeated taps while pressed are rejected. touch down/move/up support holds, slider movement and scrolling. Coordinates must lie within the display resolution. ui-tree prints non-hidden objects on the active screen, top layer and system layer with bounds, clickability and label text under the UI lock; it includes off-screen children and can temporarily stall drawing. After a drag, let scroll momentum settle and inspect fresh bounds before tapping. Physical touch and synthetic input coexist; avoid simultaneous physical interaction in repeatable tests.

eff-file list takes no filename; read/delete/publish take NAME.eff, move takes OLD.eff NEW.eff, and write takes NAME.eff OFFSET HEX. Operations use KEST_EFFECT_DESC_DIR under the SD mutex and reject non-local SD ownership. read emits hex chunks. write accepts up to 128 decoded bytes within the 256-character command limit. Offset 0 starts tmp/NAME.tmp; later offsets must equal its current length. publish renames that staged file to NAME.eff without validating descriptor content or final length. FAT refuses an existing destination with EEXIST; replacement requires explicit deletion. Wait for each result before the next write: rapid batches can lose UART bytes during SD writes. Read back published bytes to verify transfers.

Filenames use 8.3 FAT format with case-insensitive extension matching. CONFIG_FATFS_LFN_NONE=y disallows long names and NAME.eff.part staging. The tmp subdirectory is skipped by the startup loader, which otherwise attempts every non-directory entry. File operations do not refresh loaded descriptors or alter existing effects. A deliberate reboot loads a newly published descriptor through current startup; live discovery/refresh, broader state controls and diagnostics remain planned. Refresh-period tuning remains deferred at the 1 ms baseline.

The superproject tools/upload_effects.py reuses these file commands over one serial connection, validates a descriptor against default verification hashes, uses 96-byte chunks to stay within the command-line limit, skips identical destinations, and requires --replace for differing files. It checks current FPGA magic/mask and exact SD readback. Its Console.wait_startup waits for 12 seconds of carrier uptime before file dumps to avoid interleaved SD/codec boot logs. Verified library uploads and the 29-file cleanup are recorded; the superproject example-effects owner records filenames, backups and current UI discovery. These host utilities do not modify firmware or refresh its descriptor list in place.

tools/uart_console.py uses installed pyserial, opens one connection, streams input/output and writes an exclusive capture log. Run --port PORT --log LOGFILE (default baud 115200). Connection-state operations can reboot this setup; keep one persistent session during tests. The PTY escape-probe response can contaminate the first command; an empty line clears it before subsequent commands.
