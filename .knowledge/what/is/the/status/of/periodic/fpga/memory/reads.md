Scratchpad readback implements David's latest-value stream model. kest_fpga_queue_mem_read(address, data, callback) copies a request into the SPI queue without waiting or allocating per read. SPI performs the two-byte read and invokes the callback. kest_mem_slot_read_cb atomically publishes the signed sample and sets an arrival flag; a negative transport error leaves the latest good sample intact.

The existing 100 Hz control loop consumes the arrival flag and propagates current scope dependencies, coalescing multiple arrivals. It makes best-effort read attempts for enabled resources with positive read_period_ms, rounded up to 10 ms ticks; shorter periods attempt every tick. REPROGRAM suppresses resource processing. A queue rejection or absent arrival leaves operation running, with the next ordinary read providing another refresh opportunity. There are no request tokens, reply correlation, memory reply messages, per-read deadlines or retry records. The separate LVGL DMA layer remains absent; LFO timers are independent.

Callback data is borrowed until completion. Resource payload deletion markers stop new work; control retains the owning effect and its resources until pending control work is consumed and an ordered SPI callback confirms earlier reads finished. Marked memory payloads ignore arrivals. After SPI completion, control schedules final reclamation on the UI task, retaining the view until queued refreshes/timers can be cancelled there. The pipeline lifecycle owner governs release, inactive-owner retention and allocator boundaries. Queued-target ID reuse, persistence-job pointers, non-UI mutation and physical program-send failure behavior still require wider qualification.

Memory creation defaults to 10 ms; the legacy dictionary extractor defaults to 7 ms and accepts read_ms. The newer kest_extract_mem accepts only type. These descriptor acceptance differences remain explicit. Consumers atomically load the latest sample; clones copy its value/metadata with no pending arrival.
